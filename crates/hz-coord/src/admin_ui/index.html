    部署向导
    
      
    按顺序照抄到服务器上自己执行。本页不执行命令，不打开远程 shell，不签发证书，不恢复备份，也不重启服务。形态是 musl 静态二进制加 systemd，不用容器。把命令里的占位符换成你的域名与路径。细节以仓库 runbook 为准。
    

      
    
        
    1. DNS 与 SNI
    
        
    大陆云主机使用已备案域名。三条 A 记录指向同一公网 IP：coord、relay、auth。安全组放行 TCP 443、TCP 80、UDP 3478 与 UDP 3479（第二个 STUN 端口，未放行只让 NAT 判定退化为 unknown）。443 由 nginx 按 SNI 把整条连接分给三个服务，每个子域名一张只含自身名字的证书。
    
        
    dig +short coord.<域名> A
dig +short relay.<域名> A
dig +short auth.<域名> A
    
        
    
      
    

      
    
        
    2. 安装服务
    
        
    在仓库根目录执行。脚本安装 nginx、hz-coord、hz-relay、hzd，并写 systemd 单元。Kanidm 同样是原生二进制加 systemd，不是容器。dist 来自 Release 产物，或 x86_64-unknown-linux-musl 的 release 构建。
    
        
    sudo bash scripts/deploy/server-bootstrap.sh \
  --domain <域名> \
  --dist <dist 目录绝对路径> \
  --kanidm-tarball <kanidm 发布包路径或 URL，可选>
    
        
    
      
    

      
    
        
    3. 证书
    
        
    bootstrap 会先放占位自签证书。正式证书用 acme.sh，coord / relay / auth 各一张。续期由 acme.sh 的定时任务完成。测试环境可加 --self-signed。
    
        
    sudo bash scripts/deploy/certs.sh --domain <域名> --account-email <你的邮箱>
curl -fsS https://coord.<域名>/healthz
curl -fsS https://auth.<域名>/status
    
        
    
      
    

      
    
        
    4. Kanidm 与 hznet_admins
    
        
    前提是正式证书已装好。脚本创建 hznet_admins 与第一个管理员，并登记 OIDC 回调 https://coord.<域名>/admin/oidc/callback。口令与 client secret 只打印一次。只有该组成员能进入本控制台。之后加人用第二条命令。
    
        
    sudo bash scripts/deploy/kanidm-init.sh --domain <域名> --admin-name <登录名>
kanidm group add-members hznet_admins <某人>
    
        
    
      
    

      
    
        
    5. bootstrap 与首个 Node
    
        
    签发第一把 Auth Key（必须带至少一个 Tag）并让云主机自己接入。明文只显示一次。其他机器用 install.sh 后同样 hz up。要让 Node 归属某个 User，在该机器上交互登录，而不是只用 Auth Key。
    
        
    sudo bash scripts/deploy/hz-bootstrap.sh --admin <登录名> --expiry 365d --tag server
sudo hz up --auth-key <Auth Key>
hz status
curl -fsSL https://coord.<域名>/install.sh | sudo sh
sudo hz up --auth-key <Auth Key>
    
        
    
      
    

      
    
        
    6. Relay 地址
    
        
    Coordination Server 主机名是 coord.<域名> 时，install.sh 写入 HZD_RELAY_ADDR=https://relay.<域名>：Linux 在 /etc/default/hzd，macOS 在 launchd plist。已有值重跑保留。Relay 不在这个名字上时，安装前设置 HZNET_RELAY_ADDR（sudo 会清环境变量，用 sudo env）。hzd 没有对应的命令行参数。
    
        
    curl -fsSL https://coord.<域名>/install.sh | sudo sh
curl -fsSL https://coord.<域名>/install.sh | sudo env HZNET_RELAY_ADDR=https://relay.example.com:8443 sh
    
        
    
      
    

      
    
        
    7. 备份 cron
    
        
    本页的「立即备份」只触发一次打包。日常备份写在 root 的 crontab 里，由你自己添加。健康检查脚本只打印，不改文件；备份新旧不在那支脚本里，看上面的运维状态。
    
        
    0 4 * * * /bin/bash /path/to/HertzMeshNet/scripts/deploy/backup.sh --with-kanidm >> /var/log/hznet-backup.log 2>&1
sudo bash scripts/deploy/healthcheck.sh --domain <域名>
